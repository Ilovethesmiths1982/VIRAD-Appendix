# Methodological Framework



# I. Data Acquisition, Annotation, Identifier Normalization, and Coordinate Standardization


## a. Rationale

The first stage creates a traceable and internally consistent collection of viral sequences and RNA-relevant annotations. The main goal is to ensure that every later model input can be linked back to the exact source accession and genomic coordinates from which it was derived. This traceability is especially important in a multimodal workflow because sequence, annotation, conservation, structure, and host-context files are generated by different tools and must ultimately refer to the same biological record.

## b. Viral sequence acquisition

Viral genome accessions were retrieved from NCBI Entrez nuccore through Entrez E-utilities. Sayers (2022) describes the Entrez Programming Utilities as a programmatic interface for querying and retrieving records from NCBI databases. RefSeq records were prioritized because their annotation is more standardized. Additional complete-genome records were admitted under family-specific retrieval limits to increase diversity without allowing heavily sampled taxa to dominate the dataset.

Representative retrieval queries were:

{family}[Organism] AND srcdb_refseq[PROP]

and

{family}[Organism] AND "complete genome"[Title] NOT srcdb_refseq[PROP]

For every accepted record, the pipeline retained the accession/version identifier, viral family, raw nucleotide sequence, sequence length, source database, and annotation references. Raw FASTA and GFF3 files were preserved before transformation. Keeping the unmodified source files makes it possible to audit later coordinate transformations and to determine whether an inconsistency arose during retrieval, annotation processing, or downstream feature generation.

## c. Identifier normalization

The same biological record can appear with accession versions, segment labels, or tool-specific suffixes. A normalized join key was therefore created for deterministic cross-file matching, while the original source identifier was kept unchanged for provenance.

The same biological record had to map consistently across sequence files, annotations, cluster assignments, partition manifests, evolutionary outputs, UFold caches, host mappings, model windows, motif predictions, and Cas13d tables. The complete ingestion and normalization procedure is summarized in Algorithm 1. Silent many-to-one identifier collapse was not permitted unless an explicit aggregation rule was defined, as in accession-level handling of segmented genomes.

## d. RNA annotation construction

RNA-relevant supervision was assembled from NCBI GFF3 annotation and Rfam/Infernal evidence. Rfam organizes structured and non-coding RNA families using curated alignments, secondary-structure information, and covariance models (Kalvari et al., 2021). Infernal uses covariance models to search sequences for homologs that preserve both sequence and RNA-structure signals (Nawrocki & Eddy, 2013). In VIRAD, Infernal cmscan was used to identify covariance-model matches.

cmscan --cut_ga --rfam --nohmmer \\

  --tblout cmscan.tblout \\

  Rfam.cm genomes.fasta

VIRAD did not treat every coding feature as an RNA motif. Only evidence suitable for nucleotide-level RNA supervision was used to create motif targets, as summarized in Table 1. This distinction prevents ordinary protein-coding annotation from automatically becoming a positive RNA-regulatory label.

**Table 1 | RNA supervision targets**

| **Target**     | **Representation**           | **Meaning**                                              |
| -------------- | ---------------------------- | -------------------------------------------------------- |
| motif presence | nucleotide-level binary mask | whether a nucleotide belongs to an RNA-relevant interval |
| motif identity | 87-class categorical target  | motif category when a valid type label exists            |

Positions without a valid motif-type label used ignore index -1. Compatible overlapping annotations were merged deterministically. If overlapping motif-type labels could not be reconciled without an arbitrary choice, the affected example was excluded. Exclusion is preferable to forcing a formally precise label onto biologically ambiguous supervision.

## e. Coordinate standardization

All internal genomic intervals use zero-based, half-open coordinates [start,end).

**Equation 1 | Half-open interval length**

$$
L_{\mathrm{interval}} = e-s
$$

As defined in Equation 1, an interval [s,e) includes position s but excludes position e, so the number of nucleotides is exactly e-s. GFF3 coordinates were converted once from one-based inclusive coordinates during ingestion. Alignment coordinates were treated separately because gaps change alignment positions relative to genomic positions.

The neural alphabet is A, U, G, C, and N. Genomic T was converted to U for neural encoding, while DNA-form sequences were retained for tools that require T. Using one internal coordinate convention and one neural alphabet reduces the chance of off-by-one errors or DNA/RNA alphabet mismatches when modalities are joined.

**Algorithm 1 | Source-record ingestion and annotation normalization**

```text
INPUT: viral-family retrieval definitions, NCBI records, NCBI GFF3 annotations, Rfam covariance-model evidence
BEGIN
    FOR each retrieved viral record r
        REQUIRE a valid accession/version and nucleotide sequence
        PRESERVE the original source identifier and raw source files
        NORMALIZE the join identifier and nucleotide alphabet
        COLLECT RNA-relevant NCBI and Rfam/Infernal evidence
        CONVERT accepted annotation intervals to zero-based half-open coordinates
        REQUIRE 0 <= start < end <= sequence length
        RESOLVE compatible overlapping annotations deterministically
        REJECT ambiguous identifier mappings or irreconcilable motif labels
        SAVE sequence, annotations, coordinates, family, and provenance
    END FOR
RETURN normalized viral records and RNA-supervision intervals
END
```


# II. Sequence Quality Control, Redundancy Reduction, and Leakage-Controlled Partitioning


## a. Rationale

This stage prevents two common problems: low-quality sequences entering the model and highly related genomes appearing in different data partitions. The latter would create information leakage because the test set would no longer represent a sufficiently independent estimate of generalization.

## b. Whole-sequence and local-window quality control

Whole genomes shorter than 500 nt were excluded. Records with ambiguous-base fraction greater than 0.10 were rejected.

**Equation 2 | Ambiguous-base fraction**

$$
f_N=\frac{1}{L}\sum_{i=1}^{L}\mathbf{1}[x_i=N]
$$

As shown in Equation 2, L is sequence length and the indicator contributes 1 whenever the position is N. A second QC layer was applied to candidate model windows. Windows were rejected when local ambiguous-base fraction or local gap fraction exceeded 0.20. The two-level QC design prevents a globally acceptable genome from contributing to a locally poor training window.

## c. Redundancy reduction

Accepted genomes were clustered with CD-HIT-EST using 95% nucleotide identity and 90% coverage of both the longer and shorter sequence. CD-HIT was developed for efficient clustering of highly similar biological sequences (Fu et al., 2012). Clustering was performed before partition assignment so highly related genomes stayed in the same indivisible partition unit.

The rationale for this step is not simply to reduce file size. It is primarily a leakage-control mechanism: if two nearly identical genomes were placed in training and test separately, model performance could be inflated because the test example would be too similar to material already seen during training.

## d. Stratification and deterministic allocation

Records were grouped into genome/CD-HIT clusters before partition allocation. Clusters were then stratified by viral family and by whether any member contained a motif label. Within each stratum, the cluster order was shuffled using Python's random.Random(42).

For a stratum containing n clusters, the training, validation, and test allocations were calculated as shown in Equations 3a–3c:

**Equation 3a | Training-cluster allocation**

$$
n_{\mathrm{train}}=\operatorname{round}(0.70n)
$$

**Equation 3b | Validation-cluster allocation**

$$
n_{\mathrm{val}}=\operatorname{round}(0.15n)
$$

**Equation 3c | Test-cluster allocation**

$$
n_{\mathrm{test}}=n-n_{\mathrm{train}}-n_{\mathrm{val}}
$$

Python's built-in round behavior was used. No hidden minimum-per-partition rule was added for small strata. After training and validation counts were taken, the remainder was assigned to test.

**Equation 4 | Cluster-disjointness constraint**

$$
C_{\mathrm{train}}\cap C_{\mathrm{val}}=C_{\mathrm{train}}\cap C_{\mathrm{test}}=C_{\mathrm{val}}\cap C_{\mathrm{test}}=\varnothing
$$

As shown in Equation 4, a cluster can appear in only one partition. Because all member sequences inherit their cluster's assignment, this rule is stronger than checking only whether exact sequence identifiers are duplicated.

## e. Reproducibility and failure rules

The partitioning procedure is summarized in Algorithm 2. The frozen cluster-to-partition mapping is treated as immutable. If the same cluster is found in more than one partition, downstream held-out claims are invalid and the partitioning step must be rebuilt.

**Algorithm 2 | Leakage-controlled cluster partitioning**

```text
INPUT: quality-controlled viral genomes, viral family labels, motif-presence labels, seed = 42
BEGIN
    REMOVE genomes failing whole-sequence quality criteria
    CLUSTER accepted genomes with CD-HIT-EST at 95% identity and 90% bidirectional coverage
    STRATIFY clusters by viral family and motif-label presence
    FOR each stratum
        SHUFFLE complete clusters deterministically using seed 42
        ASSIGN round(0.70 n) clusters to training
        ASSIGN round(0.15 n) clusters to validation
        ASSIGN all remaining clusters to test
    END FOR
    REQUIRE no cluster identifier is shared across training, validation, or test
    PROPAGATE each cluster assignment to all member sequences and derived windows
RETURN frozen cluster-to-partition mapping
END
```


# III. Training-Only Evolutionary Conservation Modeling

## a. Rationale

Evolutionary conservation gives the model a signal describing whether a nucleotide is relatively constrained within its viral family. To prevent feature-level leakage, the evolutionary background itself is estimated using training genomes only.

Validation and test sequences may later receive conservation scores, but they are not allowed to influence the initial family alignment, distance matrix, tree, or fitted substitution model. This distinction matters because conservation is itself an input feature; allowing test genomes to shape the conservation model would leak information into the model before the final evaluation.

## b. Training multiple-sequence alignment

Training genomes from each family were aligned with MAFFT. Katoh and Standley (2013) describe MAFFT as a multiple-sequence alignment framework designed to provide accurate and computationally practical alignments across diverse sequence sets. Equal row width, nonempty content, unique membership, and agreement between each ungapped alignment row and its source sequence were required before evolutionary distances were calculated.

## c. Pairwise mismatch fraction

For aligned sequences a and b, only columns containing canonical A/C/G/T in both rows were compared.

**Equation 5 | Pairwise mismatch fraction**

$$
p_{ab}=\frac{1}{N_{ab}}\sum_{k\in M_{ab}}\mathbf{1}[a_k\ne b_k],\qquad N_{ab}=|M_{ab}|
$$

As defined in Equation 5, $M_{ab}$ is the set of directly comparable columns, and $N_{ab}=|M_{ab}|$. In plain terms, this is the fraction of comparable positions at which the two sequences differ. Columns containing gaps or noncanonical bases in either sequence are excluded because treating them as ordinary mismatches would mix missing/ambiguous information with actual nucleotide substitutions.

## d. Jukes-Cantor correction

Observed mismatch fraction can underestimate evolutionary change because the same site can mutate more than once; the correction used here is shown in Equation 6. Jukes and Cantor (1969) introduced a simple substitution model that corrects the observed fraction of differences for the possibility of repeated substitutions at the same position.

**Equation 6 | Jukes-Cantor distance**

$$
d_{ab}=-\frac{3}{4}\ln\!\left(1-\frac{4p_{ab}^{*}}{3}\right)
$$

The logarithm becomes undefined when the mismatch fraction reaches 0.75, so the saturation rule shown in Equation 7 was applied. Saturated values were therefore capped just below that limit.

**Equation 7 | Jukes-Cantor saturation cap**

$$
p_{ab}^{*}=\min\!\left(p_{ab},\,0.75-10^{-6}\right)
$$

Thus, a pair with p > 0.75 is retained as a very large but finite evolutionary distance. The cap is a numerical safeguard and is not a new biological interpretation of the Jukes-Cantor model.

## e. Zero canonical overlap

If two aligned training sequences contained no column in which both positions were canonical A/C/G/T, no evolutionary distance was assigned for that unsupported pair. No arbitrary maximum distance or graph-based substitute was introduced.

This fail-closed behavior is important because it avoids introducing unsupported evolutionary information. A missing comparison is treated as a limitation of the available alignment rather than as evidence of extreme divergence.

## f. Deterministic neighbor joining

A neighbor-joining tree was constructed from the training-only distance matrix. Neighbor joining is a distance-based tree-building method introduced by Saitou and Nei (1987). Exact ties were resolved deterministically using the lower taxon indices. Small negative branch lengths caused by numerical rounding were clamped to zero, and Newick branch lengths were written to six decimal places.

Deterministic tie handling makes repeated runs with the same distance matrix produce the same serialized tree even when multiple pairs have equal joining scores.

## g. phyloFit and phyloP

The training alignment and tree were passed to PHAST phyloFit using a REV substitution model. phyloP was then run in likelihood-ratio-test mode with CONACC scoring and refidx 0. PHAST and phyloP provide comparative-genomic tools for fitting evolutionary models and evaluating site-specific conservation or acceleration (Hubisz et al., 2011).

phyloFit --tree tree.nh --subst-mod REV --msa-format FASTA --out-root train train.fa\
 phyloP --wig-scores --method LRT --mode CONACC --msa-format FASTA --refidx 0 train.mod train.fa

Validation and test genomes were projected only after the training evolutionary background had been established. The tree and substitution model were not refitted using held-out genomes.

Raw mapped phyloP values were bounded before model input as defined in Equation 8:

**Equation 8 | Conservation feature bounding**

$$
c_i=\min\!\left(1,\max(0,x_i)\right)
$$

This is a numerical feature transformation, not probability calibration. A bounded value near 1 therefore means “high under the transformed input scale,” not “100% probability that the nucleotide is functionally important.”

## h. Reproducibility and failure rules

The complete conservation workflow is summarized in Algorithm 3. The family analysis stops if alignment widths are inconsistent, a required pair has zero canonical overlap, PHAST is unavailable, a phyloP track is empty or non-finite, or mapped conservation length disagrees with the source sequence.

**Algorithm 3 | Training-only evolutionary conservation modeling**

```text
INPUT: training genomes grouped by viral family
BEGIN
    FOR each viral family
        ALIGN training genomes with MAFFT
        REQUIRE equal alignment width, unique members, and source-sequence agreement
        FOR each sequence pair (a, b)
            IDENTIFY columns canonical in both sequences
            IF no canonical overlap exists THEN FAIL for the unsupported pair
            COMPUTE mismatch fraction over canonical-overlap columns
            APPLY Jukes-Cantor correction with saturation cap at 0.75 - 10^-6
        END FOR
        BUILD a deterministic neighbor-joining tree
        FIT a REV substitution model with phyloFit
        COMPUTE phyloP CONACC scores from the frozen training-defined model
        PROJECT validation and test sequences without refitting the tree or substitution model
        BOUND mapped conservation values to the model input range [0, 1]
    END FOR
RETURN training-defined conservation models and mapped conservation tracks
END
```


# IV. Sliding-Window Construction and Multimodal Feature Assembly

## a. Rationale

VIRAD is trained on local sequence windows rather than complete genomes. This makes it possible to align sequence, conservation, RNA structure, and supervision at exactly the same nucleotide coordinates while keeping the memory cost of structure matrices and attention manageable.

## b. Window enumeration

Training examples were complete 512-nt windows at stride 256, with window starts and completeness requirements defined in Equations 9 and 10.

**Equation 9 | Training-window start**

$$
s_k=256k
$$

**Equation 10 | Complete-window requirement**

$$
s_k+512\le N
$$

Partial trailing windows were not padded into the primary training population. This avoids creating artificial sequence content at the end of a genome and ensures that each standard training example has the same biological span.

## c. Sequence modality

Sequence was encoded as five channels corresponding to A, U, G, C, and N. Before projection, the tensor shape is [B,5,L], where B is batch size and L is window length.

## d. Conservation modality

The genomic phyloP track was sliced using the exact same [start,end) coordinates as the sequence, producing [B,L]. Coordinate identity is required so that the conservation score at model position i refers to the same nucleotide represented by sequence position i.

## e. UFold structure modality

RNA secondary structure was predicted with UFold, a deep-learning approach for RNA secondary-structure prediction (Fu et al., 2022). The retained binary contact representation is shown in Equation 11. VIRAD uses the retained UFold output as a hard binary RNA-contact matrix rather than as calibrated base-pair probabilities.

**Equation 11 | Binary RNA-contact representation**

$$
P\in\{0,1\}^{L\times L},\qquad P_{ij}=P_{ji}
$$

A value of 1 means that UFold retained a predicted contact between positions i and j; 0 means it did not. A valid all-zero contact matrix was accepted because “no retained contact” is a legitimate model output and is different from a malformed or missing cache.

A cached structure was accepted only if it had the expected key, exact shape, finite values, binary semantics, symmetry, and coordinate provenance.

## f. Host-context modality

Host context was encoded using ESM-2 esm2_t33_650M_UR50D. ESM-2 is a protein language model in which large-scale sequence learning produces rich protein representations (Lin et al., 2023). Each retained host representation has width 1,280 and is projected through a learned 1280→768 layer before entering the multimodal model.

The host representation is global context. It is not interpreted as direct evidence of a host interaction at every viral nucleotide; rather, it gives the viral sequence model access to a learned summary of the associated host-protein context.

## g. Tensor contract

**Table 2 | Model-ready tensor contract**

| **Component**         | **Shape** | **Required checks**                     |
| --------------------- | --------- | --------------------------------------- |
| nucleotide sequence   | [B,5,L]   | fixed alphabet and coordinate agreement |
| conservation          | [B,L]     | correct length and finite values        |
| UFold contacts        | [B,L,L]   | binary, finite, symmetric               |
| host vector           | [B,1280]  | width 1,280 and finite values           |
| attention mask        | [B,L]     | valid-position semantics                |
| motif-presence target | [B,L]     | same genomic interval                   |
| motif-type target     | [B,L]     | class 0–86 or ignore index -1           |
| contextual state      | [B,L,768] | shared hidden width                     |

As summarized in Table 2 and formalized in Algorithm 4, the tensor contract is a synchronization rule: if two nucleotide-level modalities do not refer to exactly the same interval, the example is rejected rather than silently shifted or padded into alignment. This requirement prevents a structurally valid tensor from being biologically misregistered to the wrong nucleotides.

**Algorithm 4 | Multimodal VIRAD example construction**

```text
INPUT: source sequence, phyloP track, UFold contact map, ESM-2 host vector, motif labels
BEGIN
    ENUMERATE complete 512-nt windows at stride 256
    FOR each accepted window [start, end)
        SLICE sequence and conservation using identical coordinates
        LOAD the corresponding 512 x 512 UFold binary contact matrix
        REQUIRE finite, symmetric, binary structure values and exact coordinate provenance
        LOAD the 1,280-dimensional ESM-2 host-context vector
        BUILD motif-presence and motif-type targets for the same interval
        REQUIRE all nucleotide-level modalities and labels have coordinate agreement
        REJECT the example if synchronization checks fail
    END FOR
RETURN synchronized model-ready multimodal examples
END
```

# V. VIRAD Multimodal Architecture

## a. Rationale

VIRAD is multimodal because it does not rely on nucleotide sequence alone. It combines sequence identity, evolutionary conservation, predicted RNA contacts, and host-associated protein context in one model. The design is intended to let the network learn relationships between modalities rather than treating each evidence source as an independent post-processing score.

## b. Shared hidden space

All four modalities are transformed to hidden width 768. Sequence is projected from five nucleotide channels. Conservation uses a 1→128→768 multilayer perceptron. The structure branch uses contact-aware message passing. Host context uses a 1280→768 projection.

The final architecture contains 68,819,416 trainable parameters. Dropout is 0.1 and stochastic depth is 0.10. Stochastic depth was originally proposed as a way to regularize deep residual networks by randomly bypassing residual transformations during training (Huang et al., 2016).

## c. Learned multimodal fusion

The model learns how strongly each modality should contribute instead of assigning fixed manual weights, as formalized in Equations 12 and 13.

**Equation 12 | Learned modality weight**

$$
w_m=\frac{\exp(g_m)}{\sum_{r\in\mathcal{M}}\exp(g_r)}
$$

**Equation 13 | Direct multimodal fusion**

$$
E_{\mathrm{mix}}=\sum_{m\in\mathcal{M}}w_mE_m
$$

The modality set contains sequence, conservation, structure, and host context. The softmax normalization ensures that the learned weights form a relative weighting across modalities rather than four unrelated unbounded coefficients.

## d. Sequence-to-structure cross-attention

A separate six-head cross-attention path uses sequence states as queries and structure states as keys and values. This allows a nucleotide representation to retrieve structural information from other positions rather than treating RNA structure as a simple scalar feature.

The attention mechanism follows the general query-key-value formulation introduced in the Transformer architecture (Vaswani et al., 2017), while VIRAD adds the biology-specific conservation and contact biases shown in Equations 14–17.

## e. Six Viroformer blocks

The fused representation passes through six Viroformer blocks with 12 self-attention heads. Hidden width 768 gives a self-attention head width of 64.

**Equation 14 | Content attention score**

$$
s_{ij}^{(h)}=\frac{\left(q_i^{(h)}\right)^{\!T}k_j^{(h)}}{\sqrt{64}}
$$

Conservation and structure contribute learned head-specific biases.

**Equation 15 | Conservation attention bias**

$$
b_{ij,\mathrm{cons}}^{(h)}=\ln\!\left(1+\max\!\left[\alpha_h(c_i+c_j),0\right]\right)
$$

**Equation 16 | Structure attention bias**

$$
b_{ij,\mathrm{struct}}^{(h)}=\beta_h P_{ij}
$$

**Equation 17 | Biologically biased attention logit**

$$
a_{ij}^{(h)}=s_{ij}^{(h)}+b_{ij,\mathrm{cons}}^{(h)}+b_{ij,\mathrm{struct}}^{(h)}
$$

These are learned inductive biases, not hard biological rules. The model can learn to increase or decrease their influence. In practical terms, conservation and predicted base pairing can make some nucleotide-to-nucleotide relationships easier for the attention layer to emphasize, but they do not force a specific biological conclusion.

Each block also contains host cross-attention and a GELU 768→3072→768 feed-forward network with residual and normalization pathways.

## f. Pair refinement and structure gating

The pair state begins from the UFold contact representation. A dense pair decoder predicts a refined pair representation from contextual nucleotide states. Pair scores are symmetrized before they are reused as structural context. The final model used one structural-refinement pass.

As summarized in Algorithm 5, a learned structure gate combines the original fused representation with the structure-updated state. The gate lets the model decide how much structure refinement should affect each nucleotide representation instead of assuming that the predicted contact map is equally reliable at every position.

**Algorithm 5 | One Viroformer block**

```text
INPUT: fused nucleotide states X, conservation track C, pair/contact state P, host context H
BEGIN
    NORMALIZE X
    COMPUTE multi-head sequence self-attention content scores
    ADD learned conservation bias derived from C
    ADD learned structure bias derived from P
    APPLY masked attention and residual update
    APPLY host cross-attention and residual update
    APPLY GELU feed-forward transformation 768 -> 3072 -> 768
    UPDATE the contextual nucleotide representation
RETURN updated nucleotide states
END
```

# VI. Multitask Learning Objectives

## a. Rationale

VIRAD is trained to solve several related tasks at once. Some tasks are always available, while others are included only when the required supervision exists. Missing labels are never treated as negative examples. This matters because forcing an absent label to zero would incorrectly teach the network that “unmeasured” means “biologically absent.”

## b. Conservation auxiliary loss

A binary conservation target is created from the bounded conservation track using threshold 0.7.

**Equation 18 | Conservation auxiliary target**

$$
y_i^{\mathrm{cons}}=\mathbf{1}[c_i>0.7]
$$

Masked binary cross-entropy with logits is then applied.

**Equation 19 | Masked binary cross-entropy**

$$
\mathcal{L}_{\mathrm{BCE}}=\frac{\sum_i m_i\,\ell_{\mathrm{BCE}}(z_i,y_i)}{\max\!\left(\sum_i m_i,1\right)}
$$

The mask ensures that padded or otherwise invalid positions do not contribute to the loss.

## c. Motif segmentation loss

The motif boundary/segmentation head combines sigmoid Dice loss and masked binary cross-entropy. Dice-style overlap objectives are commonly used when the target is spatially sparse and overlap quality matters in addition to independent position-wise classification (Milletari et al., 2016).

**Equation 20 | Dice component**

$$
\mathcal{L}_{\mathrm{Dice}}=1-\frac{2\sum_i p_i y_i}{\max\!\left(\sum_i p_i+\sum_i y_i,10^{-8}\right)}
$$

**Equation 21 | Motif segmentation objective**

$$
\mathcal{L}_{\mathrm{motif}}=\mathcal{L}_{\mathrm{Dice}}+\mathcal{L}_{\mathrm{BCE}}
$$

The Dice term rewards overlap between predicted and true motif regions, while BCE evaluates nucleotide-level classification. Combining them gives the model both a region-level overlap signal and a position-level classification signal.

## d. Optional objectives

Accessibility uses masked mean-squared error when a valid accessibility mask is present. Host prediction uses masked binary cross-entropy when host labels are available. The model also implements InfoNCE for explicitly supplied positive pairs, masked-language-model cross-entropy, and denoising MSE.

In the standard training procedure, the multitask objective was evaluated without explicitly supplied positive-pair or mutated-latent inputs. Consequently, the InfoNCE and KL-invariance terms were inactive unless their required inputs were explicitly available. This distinction ensures that the Methods describes the objectives actually optimized during training.

## e. Learned uncertainty weighting

Six grouped tasks, conservation, motif segmentation, accessibility, host prediction, contrastive learning, and the auxiliary group, are combined with homoscedastic uncertainty weighting, as defined in Equations 22 and 23. Kendall et al. (2018) proposed uncertainty-based task weighting as a way for a multitask model to learn relative contributions instead of relying entirely on manually chosen loss coefficients.

**Equation 22 | Learned uncertainty weighting**

$$
\widetilde{\mathcal{L}}_k=\frac{1}{2}\exp(-2s_k)\mathcal{L}_k+s_k
$$

**Equation 23 | Grouped uncertainty-weighted objective**

$$
\mathcal{L}_{\mathrm{group}}=\sum_{k\in\mathcal{A}}\widetilde{\mathcal{L}}_k
$$

Only active tasks are included in set A. This prevents uncertainty parameters for absent tasks from drifting during optimization.

## f. Motif-type and presence losses

Motif type uses categorical cross-entropy over 87 classes with ignore index -1 and label smoothing 0.1. The complete multitask objective is shown in Equation 24. A separate motif-presence head uses masked binary cross-entropy.

**Equation 24 | Total multitask objective**

$$
\mathcal{L}_{\mathrm{total}}=\mathcal{L}_{\mathrm{group}}+\mathcal{L}_{\mathrm{type}}+\mathcal{L}_{\mathrm{presence}}+\lambda_{\mathrm{KL}}\mathcal{L}_{\mathrm{KL}}
$$

$\lambda_{\mathrm{KL}}=0.1$. The KL term contributes only when a mutated latent state is explicitly supplied. The conditional construction of the multitask objective is summarized in Algorithm 6.

**Algorithm 6 | Multitask-loss construction**

```text
INPUT: model outputs, available task labels, validity masks
BEGIN
    INITIALIZE active task-loss set A
    IF conservation labels are available
        COMPUTE masked conservation BCE and ADD to A
    END IF
    COMPUTE motif Dice loss and masked motif BCE; ADD motif segmentation loss to A
    IF accessibility labels are available THEN ADD masked accessibility MSE to A
    IF host labels are available THEN ADD masked host BCE to A
    IF explicit contrastive inputs are supplied THEN ADD contrastive loss to A
    COMPUTE uncertainty-weighted sum over active grouped tasks
    COMPUTE motif-type cross-entropy using ignore index -1
    COMPUTE motif-presence masked BCE
    ADD KL term only when a mutated latent state is explicitly supplied
RETURN total multitask loss
END
```

# VII. Curriculum Training, Optimization, and Checkpoint Selection

## a. Rationale

Training follows a curriculum so the model first learns simpler sequence patterns and then incorporates additional biological modalities, as summarized in Table 3. Validation is used to monitor generalization and choose checkpoints, but never contributes gradients. The curriculum is a study-specific design choice rather than a claim that one universal modality order is optimal for all multimodal RNA models.

## b. Four-stage curriculum

**Table 3 | VIRAD four-stage curriculum**

| **Stage** | **Maximum epochs** | **Enabled modalities / training role** | **Initial learning rate** |
| --- | ---: | --- | ---: |
| Stage 1 | 2 | sequence only | 1 × 10⁻⁴ |
| Stage 2 | 5 | sequence + conservation + structure | 1 × 10⁻⁴ |
| Stage 3 | 5 | sequence + conservation + structure + host | 5 × 10⁻⁵ |
| Stage 4 | 43 | full multimodal/multitask optimization with validation-F1 early-stopping control | 1 × 10⁻⁵ |

The configured maximum schedule is 55 epochs.

## c. Effective batch size

**Equation 25 | Effective batch size**

$$
B_{\mathrm{eff}}=B_{\mathrm{micro}}N_{\mathrm{accum}}
$$

The final training configuration used a physical micro-batch of 4 with gradient accumulation over 8 micro-batches.

As defined in Equation 25, 32 examples contributed to each effective optimizer update even though only 4 examples were processed physically at a time. Gradient accumulation was used to preserve the intended effective batch while fitting the model within available accelerator memory.

## d. Optimization and numerical precision

Optimization used AdamW, which decouples weight decay from the adaptive gradient update (Loshchilov & Hutter, 2019), with β1=0.9, β2=0.999, weight decay 0.01, global gradient-norm clipping at 1.0, linear warmup, and cosine learning-rate decay toward 1e-6.

The final training continuation used an NVIDIA L40 46-GB GPU, BF16 for most of the network, TF32 enabled, SDPA enabled, and eight data-loader workers. A Stage-4 numerical-stability investigation localized non-finite values to separate sequence/structure and host cross-attention modules. Those cross-attention operations were therefore executed in FP32 with automatic mixed precision disabled locally and then cast back to the working dtype.

This change preserved the model architecture while improving numerical stability. It should therefore be interpreted as a precision policy, not as a change in the biological model or the number of trainable layers.

## e. EMA teacher

An exponential-moving-average teacher was maintained with decay 0.999, with the update rule shown in Equation 26. Mean-teacher approaches use a slowly updated copy of the student parameters to provide a more stable target representation over training (Tarvainen & Valpola, 2017).

**Equation 26 | EMA teacher update**

$$
\phi_t=0.999\,\phi_{t-1}+0.001\,\theta_t
$$

$\theta$ represents the current student parameters and $\phi$ the more slowly changing teacher parameters.

## f. Checkpoint selection and early stopping

Validation loss and validation F1 served different purposes during training. The selected checkpoint was updated when validation loss strictly improved, with training loss used only if validation loss was unavailable, whereas Stage-4 early stopping was governed by validation F1 using a patience of 8 and a minimum global epoch of 20. A final-state checkpoint was saved every epoch, and periodic checkpoints were written every five global epochs, retaining the four most recent files.

The training and checkpoint-selection procedure is summarized in Algorithm 7. The final training run ended at global epoch 51 and optimizer step 95,064. The selected checkpoint was identified by its SHA-256 hash: `9956c5ff779c4180f49e3e588785a36b53f1028bd9cd80bee6bdfd28b0015002`. Because checkpoint selection and early stopping used different metrics, the minimum validation loss and maximum validation F1 were not assumed to occur at the same epoch.

**Algorithm 7 | Curriculum training and checkpoint selection**

```text
INPUT: training set, validation set, four-stage curriculum, optimizer and scheduler states
BEGIN
    INITIALIZE model, optimizer, scheduler, EMA teacher, and global counters
    FOR each curriculum stage in order
        ACTIVATE the modalities and objectives assigned to that stage
        FOR each epoch in the stage
            TRAIN on training batches with gradient accumulation
            APPLY gradient clipping, optimizer update, scheduler update, and EMA update
            EVALUATE validation loss and validation F1 without gradient updates
            IF validation loss strictly improves THEN SAVE selected checkpoint
            SAVE final-state checkpoint for the epoch
            SAVE periodic checkpoint every five global epochs
            DURING Stage 4, UPDATE early-stopping state from validation F1
            IF Stage-4 stopping criteria are met THEN TERMINATE training
        END FOR
    END FOR
RETURN selected checkpoint and final training state
END
```

# VIII. Validation-Derived Interval Decoder

## a. Rationale and validation control

A deterministic interval decoder was optimized using the validation partition to reduce fragmentation, where one broad nucleotide-level probability signal can otherwise be split into many short predicted intervals. Decoder selection and threshold tuning were restricted to validation data so that downstream interval construction remained separate from model training.

Once selected, the validation-derived interval decoder parameters were frozen and used for downstream genome-scale inference and motif-catalog construction without further threshold adjustment.

## b. Frozen decoder parameters

**Table 4 | Frozen validation-derived interval-decoder parameters**

| **Parameter**             | **Frozen value** | **Exact semantics**                                 |
| ------------------------- | ---------------- | --------------------------------------------------- |
| smoothing window          | 3                | NumPy convolution with mode="same"                  |
| start threshold           | >0.50            | strict high-confidence seed                         |
| continuation threshold    | >0.40            | strict connected-region mask                        |
| merge gap                 | 24 nt            | merge if separation ≤24 nt                          |
| expansion threshold       | >0.20            | expand using smoothed probabilities                 |
| minimum length            | 20 nt            | applied after expansion                             |
| mean-confidence threshold | 0.30             | mean of smoothed probabilities after expansion      |
| post-expansion remerge    | yes              | touching/overlapping expanded intervals merge again |

As summarized in Table 4 and Algorithm 8, the decoder parameters were fixed before downstream motif discovery. The exact order of operations is part of the method. Reordering these steps can change the decoded intervals even if all numerical thresholds remain the same.

**Algorithm 8 | Validation-derived interval decoder**

```text
INPUT: nucleotide probability track p
PARAMETERS: smoothing window = 3; start > 0.50; continue > 0.40; merge gap <= 24 nt;
            expansion > 0.20; minimum length = 20 nt; mean confidence >= 0.30
BEGIN
    SMOOTH p using a length-3 same-mode convolution
    IDENTIFY high-confidence seed positions where smoothed probability > 0.50
    EXTEND each seed through connected positions where probability > 0.40
    MERGE neighboring intervals separated by at most 24 nt
    EXPAND interval boundaries while adjacent probability > 0.20
    REMOVE intervals shorter than 20 nt
    REMOVE intervals with mean smoothed probability < 0.30
    REMERGE intervals that touch or overlap after expansion
RETURN final decoded half-open intervals
END
```

# IX. Genome-Scale Inference and Motif-Catalog Construction

## a. Rationale

Training is performed on local windows, but final motif discovery must be expressed in genomic coordinates. Genome-scale inference therefore maps overlapping model predictions back to the source sequence before intervals are decoded. This prevents the same biological locus from being counted multiple times simply because it appears in several overlapping windows.

## b. Overlapping inference contexts

The nominal genome-scale design applies the frozen model to 1,024-nt contexts at stride 256. Most covered positions are therefore seen in more than one local context. Overlap gives the model multiple neighborhood views of the same nucleotide and reduces dependence on a single window boundary.

## c. Projection and overlap aggregation

Window-level probabilities are projected back to genomic coordinates and averaged, as defined in Equation 27.

**Equation 27 | Overlap-aggregated nucleotide probability**

$$
\bar{p}_i=\frac{1}{K_i}\sum_{k=1}^{K_i}p_i^{(k)},\qquad K_i>0
$$

$K_i$ is the number of inference windows that cover genomic position $i$. Averaging converts several local predictions into one genomic probability track before interval decoding.

The aggregated probability track is then decoded with the frozen validation-derived decoder for downstream catalog construction.

## d. Processed-sequence reconstruction

Where final catalog generation uses accepted cached 512-nt windows, those windows are reconstructed into contiguous processed segments at their original genomic coordinates. Overlapping cached windows must agree exactly in nucleotide identity.

Uncovered internal positions are not imputed. If an accession has a true internal gap in processed coverage, it is split into distinct contiguous segments so a prediction cannot bridge sequence that the model never observed. This rule preserves the difference between “not covered by processing” and “observed but predicted as negative.”

## e. Interval-level evidence

**Equation 28 | Mean interval conservation**

$$
\bar{c}_I=\frac{1}{|I|}\sum_{i\in I}c_i
$$

Each motif-catalog record retains accession, family, cluster, partition, segment coordinates, genomic coordinates, confidence, conservation, structure summaries, annotation overlap, supporting-window metadata, and model provenance. The full catalog-construction procedure is summarized in Algorithm 9. The interval-level conservation summary is defined in Equation 28. Retaining these fields allows every catalog entry to be traced back to the model context and source interval that produced it.

**Algorithm 9 | Genome-scale or processed-sequence motif-catalog construction**

```text
INPUT: frozen VIRAD model, source viral sequence or accepted processed windows, frozen validation-derived interval decoder
BEGIN
    TILE each contiguous inference region with overlapping contexts at stride 256
    RUN VIRAD to obtain nucleotide-level motif probabilities for each context
    PROJECT every local probability back to its source genomic coordinate
    AVERAGE probabilities across all contexts covering each genomic position
    PRESERVE uncovered internal gaps; do not impute missing sequence
    SPLIT reconstructed sequence at true internal coverage gaps when necessary
    APPLY the frozen validation-derived interval decoder to each contiguous aggregated probability track
    FOR each decoded motif interval
        SUMMARIZE confidence, conservation, structure, annotation overlap, and provenance
        RECORD accession, family, cluster, partition, and genomic coordinates
    END FOR
RETURN genome-scale VIRAD motif catalog
END
```

# X. Biological Evidence Characterization

## a. Rationale

Biological evidence characterization asks whether predicted loci show features that are consistent with known RNA biology. These analyses help prioritize candidates, but they do not convert a computational prediction into experimental proof.

## b. Annotation overlap

Predicted loci were compared with RNA-relevant NCBI and Rfam-derived annotations. Annotation-supported predictions form an external-consistency class. Predictions without annotation overlap remain **candidate RNA loci** rather than being automatically labeled novel functional motifs. Rfam-based agreement is informative because Rfam families are built around structured-RNA evidence, but absence from Rfam does not prove that a locus lacks function (Kalvari et al., 2021).

## c. Conservation and structure summaries

phyloP and UFold evidence were summarized across predicted intervals. Because both are input modalities to VIRAD, these summaries are considered supportive characterization rather than independent validation. phyloP provides comparative evolutionary evidence (Hubisz et al., 2011), whereas UFold provides a predicted RNA-contact representation (Fu et al., 2022).

Cross-window consistency may be used as an internal reproducibility measure by asking whether the same genomic interval is recovered in other windows that fully cover it. Positional recurrence within a viral family may also be summarized, but relative positional recurrence does not prove nucleotide homology or shared molecular function.

# XI. Cas13d Candidate Generation and Development-Set Construction

## a. Rationale

VIRAD motif discovery identifies candidate viral RNA regions, whereas Cas13d guide design is a downstream prioritization step that asks whether those regions contain short target sequences suitable for further experimental evaluation as crRNA spacers. Cas13 systems are RNA-targeting CRISPR effectors, and guide performance can depend on sequence composition, target context, accessibility, and other molecular features rather than target identity alone (Wessels et al., 2020). The Cas13d analyses were therefore performed as a separate, leakage-controlled development stage rather than as part of VIRAD model training.

## b. Candidate generation and sequence-level quality control

Candidate target sequences of 22–28 nt were enumerated from VIRAD-predicted motif intervals, with 23 nt used as the nominal redesign length. Candidates were required to have a GC fraction between 0.30 and 0.60 and a maximum homopolymer run of six nucleotides. These thresholds are study-specific design criteria and are not presented as universal requirements for Cas13d activity.

The genomic VIRAD interval defines the target region, whereas the target-complementary sequence constitutes the spacer portion of the Cas13d crRNA. Cas9-style sgRNA terminology was not used. A balanced development shortlist of 300 guides was retained across six represented viral families: Coronaviridae, Flaviviridae, Orthomyxoviridae, Picornaviridae, Retroviridae, and Togaviridae.

## c. Development-data firewall

Guide development was restricted to candidates originating from the training or validation partitions. Test-derived candidates were excluded before population scoring, locus-conservation analysis, structural evaluation, consensus ranking, or panel freeze. The completed development run therefore contained 300 development guides, rejected no guide for non-development provenance, and did not use the test partition.

Segmented viral accessions were handled at accession level. When segments were concatenated for population searching, adjacent segments were separated by 50 N characters. Because this separator exceeds the nominal guide length, a candidate match could not be assembled across an artificial segment boundary.

The candidate-generation procedure is summarized in Algorithm 10.

**Algorithm 10 | Cas13d development-candidate construction**

```text
INPUT: VIRAD motif catalog, training and validation partitions
BEGIN
    EXCLUDE motif-derived candidates originating from the test partition
    FOR each eligible VIRAD motif interval
        ENUMERATE target sequences of length 22-28 nt
        USE 23 nt as the nominal design length
        RETAIN candidates with GC fraction from 0.30 to 0.60
        RETAIN candidates with maximum homopolymer run <= 6
        RECORD source accession, viral family, motif identifier, genomic coordinates, and target sequence
    END FOR
    WHEN segmented accessions are concatenated for population searching
        INSERT 50 N characters between segments
    END WHEN
    CONSTRUCT the balanced development shortlist from development-partition candidates only
RETURN leakage-controlled Cas13d development candidate set
END
```

# XII. Leakage-Controlled Cas13d Development Validation

## a. Rationale

Cas13d development validation compared candidate guides using complementary computational evidence while maintaining a strict separation from the untouched test population. The analysis assessed source-excluded viral-population representation, homologous-locus conservation, RNA accessibility and energetics, complete-crRNA folding, human-transcript similarity, matched controls, and consensus ranking. None of these computational measurements was interpreted as direct evidence of Cas13d loading, cleavage, antiviral efficacy, or biological safety.

## b. Source-excluded same-family viral-population coverage

For each guide, the source accession was removed from the same-family training-plus-validation population before coverage was calculated. This source-exclusion rule prevents a guide from receiving population-support credit simply because it matches the sequence from which it was designed.

**Equation 29 | Hamming distance**

$$
H(x,y)=\sum_{i=1}^{L}\mathbf{1}[x_i \ne y_i]
$$

For each eligible accession, both the guide orientation and reverse-complement orientation were searched across all equal-length windows, and the minimum Hamming distance was retained. Source-excluded coverage at mismatch threshold $t$ was then calculated as defined in Equation 30.

**Equation 30 | Source-excluded accession coverage**

$$
\mathrm{Coverage}_t(g)=\frac{1}{|A_g|}\sum_{a\in A_g}\mathbf{1}\!\left[H_{\min}(g,a)\le t\right]\times100\%,
\qquad t\in\{0,1,2\}
$$

Here, $A_g$ is the eligible same-family development population after removal of guide $g$'s source accession. Coverage was reported at exact-match, ≤1-mismatch, and ≤2-mismatch thresholds. For 23-nt targets, population searching used an 8+8+7 seed strategy to identify candidate locations, followed by full-length 23-mer Hamming verification. Seed matches were therefore used only for computational acceleration and did not define the final mismatch count.

## c. Homologous-locus conservation

Whole-genome occurrence coverage determines whether a compatible target exists anywhere in an accession, but does not establish conservation of the corresponding biological locus. Locus-aware analysis therefore used development-only family-level multiple-sequence alignments constructed with MAFFT from training and validation accessions. The retained alignments contained 139 Coronaviridae, 152 Flaviviridae, 175 Orthomyxoviridae, 431 Picornaviridae, 396 Retroviridae, and 55 Togaviridae accessions after development-partition filtering.

For each guide, the source coordinates were mapped into the appropriate family alignment. The guide-source accession was excluded from the per-guide homologous-locus comparison, and gapped or otherwise unusable homologous fragments were not counted as sequence matches. Locus-level summaries included exact-, ≤1-mismatch-, and ≤2-mismatch support, mismatch-position profiles, mismatch-count distributions, haplotype count, major-haplotype frequency, and nucleotide entropy.

**Equation 31 | Nucleotide entropy**

$$
H_i=-\sum_{b\in\{A,C,G,T\}}p_{i,b}\log_2 p_{i,b}
$$

Lower entropy indicates that one nucleotide predominates at the homologous alignment position, whereas higher entropy indicates greater sequence variability. Locus-aware conservation and whole-genome occurrence coverage were retained as distinct evidence types because they answer different biological questions.

## d. Target accessibility, guide self-structure, and duplex energetics

RNA accessibility and thermodynamic descriptors were calculated with ViennaRNA tools (Lorenz et al., 2011). For each analysis context of length $n$, RNAplfold was run with window length `-W min(150,n)`, maximum base-pair span `-L min(100,max(1,n-1))`, and maximum unpaired-region length `-u 28`. For a candidate target of length $L_g$ beginning at zero-based context offset $o$, accessibility was read from the RNAplfold `*_lunp` output at row $o+L_g$ and column $L_g$, corresponding to the reported probability that the complete guide-length target interval was unpaired under the RNAplfold model. Guide self-structure was evaluated with RNAfold using the target-complementary spacer, and guide-target interaction energy was evaluated with RNAduplex using the antisense guide and corresponding target sequence.

These quantities are computational thermodynamic estimates rather than measurements of intracellular RNA folding or Cas13d cleavage. They were therefore used to characterize whether a candidate was computationally consistent with an accessible target, limited guide self-structure, and favorable guide-target pairing.

## e. Complete-crRNA structural evaluation

The completed development run additionally included complete-crRNA folding. Each complete crRNA was represented as the direct-repeat sequence `AACCCCTACCAACTGGTCGGGGTTTGAAAC` followed by the target-complementary spacer, and the combined RNA was folded with RNAfold to obtain its predicted minimum free energy. The direct-repeat sequence is reported here as the exact sequence used in the computational analysis; no ortholog-specific biological claim is inferred from the sequence alone.

Complete-crRNA folding was treated as an additional structural descriptor rather than proof of correct Cas13d loading or functional crRNA formation in cells.

## f. Human-transcript similarity screening

Potential human-transcript similarity was evaluated against the GENCODE v49 human transcriptome using Bowtie2 (Langmead & Salzberg, 2012). Screening used end-to-end alignment with one seed mismatch permitted (`-N 1`), seed length 15 (`-L 15`), and up to 100 reported alignments per guide (`-k 100`). For each guide, the analysis retained the number of reported transcript alignments, the closest reported human transcript, and the smallest reported NM mismatch count.

Because the search reports at most 100 alignments per guide, the alignment count is a capped similarity-burden descriptor and not an exhaustive biological off-target assessment. Transcript similarity alone also does not account for transcript abundance, cell type, RNA structure, or actual Cas13d cleavage.

## g. Matched controls

A matched control sequence was sampled from the same source genome within ±500 nt of the guide start. Candidate controls overlapping the guide locus were excluded. Eligible controls had the same length as the guide, contained no ambiguous nucleotide, and had a GC fraction within 0.05 of the guide. Randomization used seed 42 plus the guide-source start coordinate, making control selection reproducible for a fixed source genome.

Matched controls reduce obvious compositional and local-context differences between selected guides and nearby sequence controls, but they are not assumed to be biologically equivalent loci.

## h. Consensus guide ranking

Development ranking integrated the available evidence streams as direction-aware percentile ranks. Positive-direction metrics included exact population coverage, one-mismatch population coverage, homologous-locus exact coverage, target accessibility, VIRAD motif conservation, and VIRAD motif confidence. Negative-direction metrics included the number of reported human-transcript alignments and homologous-locus mean entropy. Tied values received the mean percentile rank of the tied observations.

**Equation 32 | Available-metric percentile consensus score**

$$
S_g=\frac{1}{|M_g|}\sum_{m\in M_g}r_{m,g}
$$

Here, $M_g$ is the set of available ranking metrics for guide $g$, and $r_{m,g}$ is its direction-corrected percentile rank for metric $m$. Missing optional evidence was omitted rather than imputed. External activity-model scores were not included in the completed development run and therefore did not contribute to the final development consensus score.

Guides were ordered by descending consensus score, followed by descending exact population coverage, descending one-mismatch population coverage, and lexicographic target-sequence order. The consensus score is a relative prioritization index and is not a calibrated probability of Cas13d activity.

## i. Ranking robustness

Ranking robustness was assessed by recomputing guide order under prespecified evidence subsets using the evidence available in the completed development run, including sequence-only evidence and accessibility-plus-sequence evidence. These analyses were used to determine whether prioritization was strongly dependent on a single evidence family; they did not constitute additional candidate-selection cycles.

The full development-validation procedure is summarized in Algorithm 11.

**Algorithm 11 | Leakage-controlled Cas13d development validation**

```text
INPUT: development guide candidates, train+validation viral population, development-only family MSAs, human transcriptome
BEGIN
    FOR each guide g
        REMOVE the source accession from same-family population coverage analysis
        COMPUTE exact, <=1-mismatch, and <=2-mismatch source-excluded population coverage
        MAP the source locus into the corresponding development-only family alignment
        EXCLUDE the source accession from homologous-locus comparison
        COMPUTE locus mismatch profiles, entropy, haplotypes, and major-haplotype frequency
        COMPUTE target accessibility with RNAplfold
        COMPUTE spacer self-folding with RNAfold
        COMPUTE guide-target duplex energy with RNAduplex
        FOLD the complete crRNA using the specified direct repeat plus target-complementary spacer
        SCREEN the guide against the GENCODE v49 human transcriptome with Bowtie2
        GENERATE a reproducible nearby matched control when eligible
        CONVERT available ranking evidence to direction-aware percentile ranks
        COMPUTE the consensus score without imputing unavailable optional evidence
    END FOR
    RANK guides using the prespecified deterministic tie-breakers
    RECOMPUTE prespecified sensitivity rankings without changing the candidate universe
RETURN development-validation table and ranked guide list
END
```

# XIII. Cas13d Panel Freeze and Untouched Test Evaluation

## a. Rationale

The final Cas13d panel was selected using development information only and rendered immutable before the untouched test population was evaluated. This design separated guide development from final generalization assessment: test data were used only to measure the already-frozen panel and did not influence guide selection, panel size, ranking criteria, mismatch thresholds, or post hoc guide replacement.

## b. Panel freeze and integrity control

A fixed panel size of three guides per viral family was declared before test evaluation. Within each family, guides were ordered by ascending development rank, then descending consensus score, and finally by target sequence. The first three guides per family were retained, producing an 18-guide frozen panel spanning Coronaviridae, Flaviviridae, Orthomyxoviridae, Picornaviridae, Retroviridae, and Togaviridae.

The development-validation table and frozen panel were each hashed with SHA-256. The development-table hash was `d519a20c4280265becb2d66fa4f3194f40318433f9d21f65704caa525aa99011`, and the frozen-panel hash was `01bdfcafd1577a5da497ad5a96a11c38a715f5598792542240a35de85631f393`. The freeze record also retained the panel size, deterministic selection rule, and an explicit statement that test data were not used for selection.

Before test evaluation, the observed frozen-panel hash was recomputed and required to match the recorded SHA-256 value exactly. A mismatch would have terminated evaluation. The observed hash matched the recorded frozen-panel hash, confirming that the evaluated panel was byte-for-byte identical to the panel frozen before test inspection.

## c. Guide-level untouched-test coverage

Each frozen guide was searched only against same-family accessions assigned to the untouched test partition. The final test population comprised 243 accessions across the six represented families: 25 Coronaviridae, 29 Flaviviridae, 31 Orthomyxoviridae, 78 Picornaviridae, 70 Retroviridae, and 10 Togaviridae. Because all guides originated from development data, source exclusion was not required during the untouched-test stage. For each guide, exact-match, ≤1-mismatch, and ≤2-mismatch coverage were computed using the same full-length Hamming-distance definition used during development analysis.

The development-only family MSAs used for guide development were not reused for test-stage locus analysis. The untouched-test assessment therefore evaluated sequence-occurrence coverage directly within the same-family test population, preserving separation between development-only homologous-locus analysis and final test evaluation. No guide redesign, replacement, reselection, threshold tuning, or panel-size adjustment was performed after test results were inspected.

## d. Panel-level union coverage

**Equation 33 | Panel union-coverage set**

$$
A^{\mathrm{test}}_{\mathrm{panel},t}=\bigcup_{g\in G}A^{\mathrm{test}}_{g,t}
$$

**Equation 34 | Panel-level untouched-test coverage**

$$
\mathrm{Coverage}_{\mathrm{panel},t}=\frac{\left|A^{\mathrm{test}}_{\mathrm{panel},t}\right|}{|A_{\mathrm{test}}|}\times100\%
$$

For panel-level evaluation, each test accession was counted once in the family-level union even when multiple frozen guides covered the same accession. This prevented redundant guides from artificially inflating panel coverage. The prespecified panel-level mismatch threshold was ≤2 mismatches; guide-level exact-match and ≤1-mismatch values were retained as complementary summaries.

The completed freeze and untouched-test procedure is summarized in Algorithm 12.

**Algorithm 12 | Cas13d panel freeze and untouched test evaluation**

```text
INPUT: completed development ranking, panel size = 3 guides per family, untouched same-family test population
BEGIN
    FOR each represented viral family
        ORDER guides by development rank, consensus score, then target sequence
        SELECT the first three guides
    END FOR
    FREEZE the resulting 18-guide panel before test inspection
    RECORD the development-table hash, panel hash, panel size, and deterministic selection rule
    RECOMPUTE and VERIFY the frozen-panel SHA-256 hash before test evaluation
    ABORT evaluation if the observed panel hash differs from the recorded frozen hash
    FOR each frozen guide
        SEARCH only same-family test accessions
        COMPUTE exact, <=1-mismatch, and <=2-mismatch guide-level coverage
    END FOR
    COMPUTE family-level panel union coverage at the prespecified <=2-mismatch threshold
    PROHIBIT redesign, replacement, reselection, threshold tuning, or post-test optimization
RETURN untouched-test guide-level and panel-level coverage results
END
```

# XIV. Statistical Analysis and Uncertainty

## a. Biological unit of analysis

Overlapping windows are not automatically treated as independent biological observations. Sequence-, accession-, cluster-, or family-level grouping is used according to the scientific question. This is important because two overlapping windows from the same viral genome share much of their sequence and cannot be treated as if they were independent organisms.

## b. Paired bootstrap uncertainty

Paired bootstrap comparisons and a family-stratified paired bootstrap were performed using 10,000 replicates and seed 42. In the stratified procedure, each family is resampled with replacement at its original family-specific sample size, and the sampled strata are concatenated before the paired mean difference is calculated.

**Equation 35 | Bootstrap paired mean difference**

$$
\Delta^{*(b)}=\frac{1}{n}\sum_{i\in S_b}(a_i-b_i)
$$

**Equation 36 | Percentile bootstrap interval**

$$
\mathrm{CI}_{0.95}=\left[Q_{0.025}(\Delta^{*}),\,Q_{0.975}(\Delta^{*})\right]
$$

As defined in Equations 35 and 36, the reported 95% interval uses the 2.5th and 97.5th percentiles of the bootstrap replicate distribution. Resampling within family preserves the broad family composition of the comparison instead of allowing one highly represented family to dominate a replicate by chance.

## c. Multiple-testing correction

Multiple-testing adjustment used Benjamini-Hochberg adjusted p-values and Holm family-wise adjusted p-values, as appropriate to the analysis. Benjamini and Hochberg (1995) introduced false-discovery-rate control for multiple testing, whereas Holm (1979) proposed a sequential family-wise error procedure. The correction used for a particular analysis must be declared with that analysis rather than chosen after observing which correction produces significance.

## d. Software and computational-environment provenance

The primary VIRAD software environment was declared in the project environment specification and included Python 3.10, PyTorch 2.0.1 with CUDA 11.8 support, torchvision 0.15.2, torchaudio 2.0.2, CD-HIT 4.8.1, MAFFT 7.520, Infernal 1.1.5, Biopython 1.81, and torch-geometric 2.3.1. Host-context embeddings used the ESM-2 `esm2_t33_650M_UR50D` model. Production UFold inference used upstream UFold commit `75bd9acc83826059682dfca9d3659df66b132cd1`, with the VIRAD runtime-compatibility patch preserved in the project scripts.

The final local Cas13d environment used ViennaRNA 2.4.7 for the RNAfold/RNAplfold/RNAduplex analyses. PHAST was declared in the primary environment but its exact package release was not pinned in the archived environment specification, and the Bowtie2 executable release used for the final transcript screen was not separately archived. These unpinned release identifiers are therefore not reconstructed retrospectively. Instead, reproducibility for those components is anchored by the preserved executable command lines and parameters, the GENCODE v49 transcript reference, the frozen VIRAD checkpoint SHA-256, the development-table SHA-256, the frozen Cas13d panel SHA-256, the deterministic random seeds, and the repository implementation state. This distinction prevents unverified software-version claims while retaining the exact computational settings needed to reproduce the reported analyses.
